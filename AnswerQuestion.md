 # Контрольні питання — Варіант 17

## 1. Для чого призначений Collections Framework?

Collections Framework — це уніфікована архітектура (набір інтерфейсів, реалізацій та алгоритмів) для зберігання та обробки груп об'єктів. Вона надає готові структури даних (списки, множини, черги, відображення) та алгоритми над ними (сортування, пошук, перемішування), що позбавляє необхідності писати їх самостійно, підвищує продуктивність і читабельність коду та забезпечує єдиний інтерфейс роботи з різними структурами.

## 2. В чому полягає різниця між масивами та колекціями?

| Масиви | Колекції |
| :--- | :--- |
| Фіксований розмір, що задається при створенні | Динамічний розмір, що змінюється під час роботи |
| Можуть зберігати як примітиви, так і об'єкти | Зберігають лише об'єкти (для примітивів використовуються класи-обгортки) |
| Мають лише базові можливості (доступ за індексом, `length`) | Мають багато методів: `add`, `remove`, `contains`, `sort`, `addAll` тощо |
| Не мають готових різних структур даних | Існують різні реалізації (список, множина, черга, відображення) |

## 3. Які особливі властивості є у списків порівняно з іншими типами колекцій?

* Список (`List`) є **впорядкованою** колекцією: елементи зберігаються у порядку додавання.
* Доступ до елементів можливий **за індексом** (`get`, `set`, `add(index, e)`, `remove(index)`).
* Допускаються **дублікати** елементів (на відміну від `Set`).
* Допускається `null` (залежно від реалізації).
* Є додаткові можливості: пошук за індексом (`indexOf`, `lastIndexOf`), підсписки (`subList`), спеціальний двонапрямний ітератор `ListIterator`.

## 4. Чим списки відрізняються від масивів?

* Розмір списку змінюється динамічно, а розмір масиву — фіксований.
* Список зберігає лише об'єкти, масив може зберігати і примітиви.
* Список має готові методи для додавання, видалення, пошуку елементів, а масив — лише доступ за індексом.
* Списки можуть бути типізовані за допомогою узагальнень (`List<T>`), що забезпечує перевірку типів на етапі компіляції.
* Список — це інтерфейс із різними реалізаціями (`ArrayList`, `LinkedList`), а масив — вбудована конструкція мови.

## 5. Чим ArrayList відрізняється від LinkedList? Який з них у яких випадках краще використовувати?

* **ArrayList** — реалізація на основі динамічного масиву. Доступ за індексом — $O(1)$, вставка/видалення в середині — $O(n)$ (зсув елементів), додавання в кінець — амортизовано $O(1)$. Займає менше пам'яті на елемент.
* **LinkedList** — реалізація на основі двозв'язного списку. Доступ за індексом — $O(n)$, вставка/видалення на початку, в кінці або через ітератор — $O(1)$. Кожен вузол містить додаткові посилання, тому пам'яті потрібно більше. Також реалізує інтерфейс `Deque`.

**Коли використовувати:**
* `ArrayList` — коли переважають читання та доступ за індексом, а вставок/видалень в середині мало (найчастіший вибір за замовчуванням).
* `LinkedList` — коли часто виконуються вставки та видалення на початку/в кінці списку або в середині під час проходу ітератором, а також коли потрібна черга чи дек.

## 6. Що таке Iterator? В чому полягають переваги використання ітератора у порівнянні з класичним циклом `for(int i=0; i<collection.size(); i++) { /* ... */ }`?

**Iterator** — це інтерфейс (патерн «Ітератор»), що надає єдиний спосіб послідовного обходу елементів колекції без розкриття її внутрішньої будови. Основні методи: `hasNext()`, `next()`, `remove()`.

**Переваги:**
* Універсальність: працює з будь-якою колекцією (`List`, `Set`, `Queue`), навіть якщо в ній немає індексів.
* Ефективність: для `LinkedList` виклик `get(i)` у циклі має складність $O(n)$ на кожен виклик (загалом $O(n^2)$), а ітератор обходить колекцію за $O(n)$.
* Безпечне видалення елементів під час обходу через `iterator.remove()` (у циклі з індексом доводиться вручну коригувати `i`).
* Код не залежить від конкретного типу колекції та не потребує знання її розміру.
* Захист від одночасної модифікації (fail-fast: `ConcurrentModificationException`).

## 7. Що таке типізовані та нетипізовані колекції?

* **Типізовані колекції** — колекції, для яких за допомогою узагальнень (generics) вказано тип елементів, наприклад `ArrayList<Employee>`. Компілятор перевіряє типи під час компіляції, а явне приведення типу при отриманні елементів не потрібне.
* **Нетипізовані колекції** — колекції без вказання типу (raw types), наприклад `ArrayList`. Вони зберігають елементи типу `Object`, тому при отриманні елемента потрібне явне приведення типу, а помилки типів виявляються лише під час виконання (`ClassCastException`).

## 8. Для чого потрібен інтерфейс RandomAccess?

`RandomAccess` — це **маркерний інтерфейс** (не містить методів). Він позначає, що клас списку підтримує швидкий (за сталий час $O(1)$) довільний доступ до елементів за індексом (наприклад, `ArrayList`). Алгоритми (наприклад, у `Collections`) можуть перевірити `list instanceof RandomAccess` і обрати оптимальну стратегію обходу: цикл з індексом для `RandomAccess`-списків та ітератор для послідовних (наприклад, `LinkedList`).

## 9. Чим Collection відрізняється від Collections?

* **`Collection`** — це **інтерфейс** (`java.util.Collection`), корінь ієрархії колекцій, від якого успадковуються `List`, `Set`, `Queue`. Описує базові операції: `add`, `remove`, `contains`, `size`, `iterator` тощо.
* **`Collections`** — це **утилітний клас** (`java.util.Collections`) зі статичними методами для роботи з колекціями: `sort`, `reverse`, `shuffle`, `max`, `min`, `binarySearch`, `unmodifiableList`, `synchronizedList` тощо.
